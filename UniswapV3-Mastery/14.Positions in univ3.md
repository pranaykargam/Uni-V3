
# 🦄 Uniswap V3 — Positions

# Part-01⭐️
## 1. What is a Position?
A **position** is a record of an LP's liquidity contribution within a specific price range.

## 2. V2 vs V3

- **Uniswap V2:** LPs receive fungible ERC-20 LP tokens representing their pool share.
- **Uniswap V3:** LPs choose a price range (`tickLower`, `tickUpper`), so liquidity and fees must be tracked per position.

## 3. Why Positions?
- Track each LP's liquidity and price range.
- Calculate fees earned by each position.
- Allow liquidity to be added or removed correctly.

## 4. Important Parameters

```solidity
mint(
    address recipient,
    int24 tickLower,
    int24 tickUpper,
    uint128 amount,
    bytes calldata data
)
```

- `recipient` → Position owner in pool accounting.
- `tickLower` / `tickUpper` → Price range boundaries.
- `amount` → Liquidity amount, **not token amount**.
- `data` → Data passed to the mint callback.

## 5. Position Identification

The core pool identifies a position using:

```solidity
keccak256(
    abi.encodePacked(
        owner,
        tickLower,
        tickUpper
    )
);
```

- Same owner + same ticks → **Existing position modified**.
- Same owner + different ticks → **Different position**.

## 6. Key Functions & Concepts

- `mint()` → Adds liquidity.
- `burn()` → Removes liquidity.
- `positions` mapping → Stores position accounting.
- `NonfungiblePositionManager` → Can represent positions as ERC-721 NFTs.

**Note:** Core `mint()` does not itself mint an NFT.

## 🧠 Remember

**Pool = Market | Position = Owner + Tick Range + Liquidity + Fee Accounting**

V3 positions enable concentrated liquidity and position-specific fee accounting.
