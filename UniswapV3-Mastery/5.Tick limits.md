# Uniswap V3: Min & Max Tick 

Uniswap V3 limits prices through tick bounds: **MIN_TICK = -887,272** and **MAX_TICK = 887,272**. These bounds exist because `sqrtPriceX96` is stored as `Q64.96` and cannot represent prices above `2^128`.

## Core Formulas

```text
price(tick) = 1.0001 ^ tick

tick = log base 1.0001 (price)

sqrtPrice(tick) = 1.0001 ^ (tick / 2)

price = sqrtPrice ^ 2

sqrtPriceX96 = sqrtPrice * 2^96
```

Example at tick `100`:

```text
sqrtPrice = 1.0001 ^ (100 / 2)
          = 1.0001 ^ 50
          ≈ 1.0050122696

price = 1.0050122696 ^ 2
      ≈ 1.01005
```


## Why MAX_TICK Is 887,272

The maximum price representable by `Q64.96` is:

```text
MAX_PRICE = 2^128
```

Convert this maximum price into a tick:

```text
MAX_TICK = log base 1.0001 (2^128)
         ≈ 887,272
```

So any tick above `887,272` would imply a price too large for the protocol to store.

```python
from math import log

log(2**128, 1.0001)  # ≈ 887272
```

## Why MIN_TICK Is -887,272

The minimum tick is simply the negative of the maximum:

```text
MIN_TICK = -MAX_TICK
         = -887,272
```

This gives the minimum price:

```text
MIN_PRICE = 1.0001 ^ (-887,272)
          = 2^-128
```

The symmetry makes sense because if token X’s price versus token Y is `p`, then token Y’s price versus token X is `1 / p`.
## Sqrt Price Limits

Uniswap stores the **square root of price**, not price itself, in `sqrtPriceX96`.

For the minimum:

```text
MIN_SQRT_PRICE = 1.0001 ^ (-887,272 / 2)
               = 1.0001 ^ (-443,636)

MIN_SQRT_RATIO = MIN_SQRT_PRICE * 2^96
               ≈ 4,295,128,738.152353
```

This is rounded **up** to:

```solidity
uint160 MIN_SQRT_RATIO = 4295128739;
```

Rounding down would allow a price slightly below the minimum tick, producing tick `-887273`, which is invalid.

For the maximum:

```text
MAX_SQRT_PRICE = 1.0001 ^ (887,272 / 2)
               = 1.0001 ^ 443,636

MAX_SQRT_RATIO = MAX_SQRT_PRICE * 2^96
```

```solidity
uint160 MAX_SQRT_RATIO =
    1461446703485210103287273052203988822378723970342;
```

## Constants Cheat Sheet

| Constant | Value | Meaning |
|---|---:|---|
| `MIN_TICK` | `-887272` | Lowest allowed tick |
| `MAX_TICK` | `887272` | Highest allowed tick |
| `MIN_SQRT_RATIO` | `4295128739` | Lowest allowed `sqrtPriceX96` |
| `MAX_SQRT_RATIO` | `1461446703485210103287273052203988822378723970342` | Highest allowed `sqrtPriceX96` |

## Why `int24`?

To store `887,272`, you need about `20` bits. Since ticks can be negative, you need one extra sign bit, so `21` bits total.

Solidity only allows signed integer sizes in multiples of `8` bits, so the smallest valid type is:

```solidity
int24 tick;
```

## Audit Tips

- A tick outside `[-887272, 887272]` is invalid.
- `sqrtPriceX96` must stay within `[MIN_SQRT_RATIO, MAX_SQRT_RATIO]`.
- `MIN_SQRT_RATIO` is rounded up, not down, to prevent crossing below `MIN_TICK`.
- Price and sqrt price are linked by squaring: `price = sqrtPrice ^ 2`.
- `int24` is the smallest Solidity signed integer type that safely holds all valid tick values.

## Quick Workflow

```text
Given tick i
   ↓
sqrtPrice = 1.0001 ^ (i / 2)
   ↓
sqrtPriceX96 = sqrtPrice * 2^96
   ↓
Check:
MIN_SQRT_RATIO <= sqrtPriceX96 <= MAX_SQRT_RATIO
   ↓
price = sqrtPrice ^ 2
```
