# Uniswap V3 — Tick Spacing

Tick spacing controls which ticks can be used as liquidity-position boundaries. It is set from the pool’s fee tier and directly affects position precision, tick crossings, and swap gas. 
## Core formulas



Tick \(i\) represents the raw token1/token0 price; adjust for token decimals when interpreting it. [uniswapv3book](https://uniswapv3book.com/milestone_0/uniswap-v3.html)



A position boundary tick \(i\) is valid only if it is divisible by the pool’s tick spacing \(s\). For \(s=10\), ticks \(-20, -10, 0, 10, 20\) are valid; tick 15 is not. [rareskills](https://rareskills.io/post/uniswap-v3-tick-spacing)



Uniswap stores fees in hundredths of a basis point: fee `500` is 0.05%, `3000` is 0.30%, and `10000` is 1%. [github](https://github.com/Uniswap/v3-core/blob/main/contracts/UniswapV3Factory.sol)

## Fee tier → tick spacing

| Fee value | Fee | Default tick spacing |
|---:|---:|---:|
| 100 | 0.01% | 1 |
| 500 | 0.05% | 10 |
| 3000 | 0.30% | 60 |
| 10000 | 1.00% | 200 |

The factory stores this in `feeAmountTickSpacing`; the original deployment sets 500→10, 3000→60, and 10000→200, while governance can enable additional fee tiers. [rareskills](https://rareskills.io/post/uniswap-v3-tick-spacing)

## Low vs high spacing

| Tick spacing | Liquidity precision | Likely swap gas |
|---|---|---|
| Low, e.g. 1 | Finer price-range placement | More possible tick crossings |
| High, e.g. 200 | Coarser price-range placement | Fewer possible tick crossings |

Eligible ticks are not necessarily initialized ticks. Swap gas depends on the initialized ticks actually crossed, not merely on spacing. [rareskills](https://rareskills.io/post/uniswap-v3-tick-spacing)

## Audit checks

- Verify `pool.tickSpacing()` matches `factory.feeAmountTickSpacing(pool.fee())`.
- Check that `mint` rejects lower/upper ticks not divisible by spacing.
- Test negative ticks and bitmap-word boundaries in `TickBitmap.nextInitializedTickWithinOneWord`.
- Confirm tick crossing updates `liquidityNet`, `feeGrowth*`, and active liquidity correctly.
- Check bounds: valid ticks range from -887,272 to 887,272; factory caps spacing below 16,384. [github](https://github.com/Uniswap/v3-core/blob/main/contracts/UniswapV3Factory.sol)

## Useful Foundry checks

```bash
cast call "$POOL" "fee()(uint24)" --rpc-url "$RPC_URL"
cast call "$POOL" "tickSpacing()(int24)" --rpc-url "$RPC_URL"
cast call "$FACTORY" "feeAmountTickSpacing(uint24)(int24)" 100 --rpc-url "$RPC_URL"
```
